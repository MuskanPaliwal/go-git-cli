Confirmed findings on the published head

Standards, act on:

1. P1: resolveWritePath calls filepath.Abs/Clean before resolving filesystem components. A symlink followed by a parent-directory component can make a write replace a different existing config than Git does, with exit 0.
2. P1: explicitWriteLocation tests whether the file string is nonempty. An explicitly empty --file argument is treated as omitted and silently writes repository config. Git rejects that invocation. The read selector has the same presence-versus-value issue.
3. P1: GIT_CONFIG is ignored by read/write selection. A command intended to mutate an environment-selected config instead changes repository config and exits 0. Git honors the selector.
4. P2: discoverGitDir accepts an empty Git metadata directory as a repository, allowing a default write to create its config. Git rejects this case. Validate repository structure before granting mutation authority.

Spec, act on:

1. The parser rejects a valid UTF-8 BOM config with exit 128; Git reads it. A BOM in a global config can block ordinary inspection.
2. The onbranch wildcard condition matches an absent branch represented by an empty string. Separately, POSIX character classes such as onbranch:[[:alpha:]]* fail to match an alphabetic branch.
3. A relative include.path supplied through -c is accepted against a synthetic command-line file origin. Git rejects relative command-line includes with “relative config includes must come from files.” Absolute command-line includes are valid. The earlier checkpoint explicitly intended relative-include support, but the review reproduced that this disagrees with native Git.
4. expandPath lexically normalizes the suffix after home expansion, changing path identity when symlinks and parent-directory components are involved. Git preserves that suffix.

Consider, not ranked as primary blockers:

- Explicit --system incorrectly fails when GIT_CONFIG_NOSYSTEM=1; Git still permits explicit access.
